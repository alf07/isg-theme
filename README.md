# ISG — тестовое задание на WordPress

**Автор:** Роман Литвиненко  
**Тип проекта:** демонстрационная реализация по тестовому заданию. Это не официальный сайт ISG и не готовый к промышленному запуску продукт.

**Демо сайта:** [romaaltf.beget.tech](http://romaaltf.beget.tech/)  
**Статический макет:** `design-preview/index.html` — откройте файл в браузере, чтобы посмотреть основные экраны без установки WordPress.

## Что реализовано

Проект разделён на классическую тему WordPress и отдельный плагин функциональности. Тема отвечает за представление, а плагин — за типы контента, метаполя, настройки, создание демоданных и демонстрационные интеграции.

| Область | Что можно посмотреть или проверить | Статус и границы |
|---|---|---|
| Главная страница | Первый экран, основные секции, новости, карточки продуктов и решений, направления компании, вакансии, примеры внедрений, шапка и подвал | Страница и секции собраны в шаблоне темы. Часть контента выводится из WordPress, часть служит демонстрационным наполнением. Настройки позволяют менять предусмотренные тексты, скрывать секции, менять порядок управляемых секций и менять два цвета. Полноценного визуального конструктора произвольных блоков нет. |
| Навигация и страницы | Меню сайта, поиск WordPress, страница 404, страницы отдельных решений и услуг, архивы | Для меню используются стандартные средства WordPress. Ссылка «Купить» должна вести в магазин, а не на страницу случайного товара. |
| Редактируемые сущности | Решения, услуги, вакансии, партнёры/кейсы | Это отдельные типы записей WordPress с архивными и индивидуальными страницами. Для записей предусмотрены дополнительные поля и группировка решений/услуг. Все стартовые материалы явно отмечены как демо. |
| Магазин | Каталог WooCommerce, категории, страницы товаров, оформление магазина средствами темы | Подключены шаблоны и стили WooCommerce. Демотовары намеренно создаются без цены и не предназначены для реального заказа. Корзина и оформление заказа относятся к стандартной функциональности WooCommerce и требуют настройки магазина и товара с ценой. |
| Управление оформлением | Тексты первого экрана и описания компании, кнопки, подписи подвала, видимость и порядок основных секций, основной и акцентный цвета | Настраивается в **Внешний вид → Настройки темы ISG**. Логотип и меню задаются штатными средствами WordPress. Это не полноценный визуальный редактор всего шаблона. |
| Демонстрационные интеграции | Оплата, цифровая выдача, AI-помощник, передача обращения в Telegram | Четыре административных сценария-заглушки. Они показывают структуру ответа и идентификатор операции, но не обращаются к внешним сервисам. |
| Основа мультиязычности | Строки темы, переключатель языков, регистрация сущностей для перевода, генерация вариантов EN/RU | Требуется установить и настроить Polylang или WPML. Для полного перевода магазина WooCommerce требуется совместимое расширение. Машинный перевод отдельно не подключён. |

## Как запустить проект

### Требования

- WordPress 6.6 или новее;
- PHP 8.1 или новее;
- WooCommerce — для проверки магазина;
- Polylang или WPML — для проверки языковых версий;
- совместимое дополнение WooCommerce для полноценного мультиязычного магазина.

Тема и плагин находятся в каталоге `release/` и устанавливаются раздельно. Архив всего репозитория предназначен для просмотра исходников, а не для загрузки целиком в поле «Загрузить тему».

### Установка через админ-панель WordPress

1. Создайте тестовую установку WordPress и войдите под пользователем с правами администратора.
2. Откройте **Внешний вид → Темы → Добавить новую → Загрузить тему**. Загрузите `release/isg-theme-0.2.4.zip`, установите и активируйте тему.
3. Откройте **Плагины → Добавить новый → Загрузить плагин**. Загрузите `release/isg-site-0.4.7.zip`, установите и активируйте плагин.
4. Установите и активируйте WooCommerce. Завершите его первоначальную настройку, если проверяете каталог.
5. Если проверяете мультиязычность, сначала установите Polylang или WPML и настройте английский (`en`) основным языком, русский (`ru`) дополнительным. После установки проверьте языковые URL, переводы записей, меню и страницы магазина.
6. Откройте **ISG Site → Демо-наполнение** и нажмите **Создать недостающий демо-контент**. Повторный запуск предусмотрен для добавления недостающих записей без перезаписи уже существующего редакционного контента.
7. Откройте **Настройки → Постоянные ссылки** и нажмите **Сохранить изменения**, если после установки архивы возвращают 404.

Если WooCommerce активирован уже после первоначальной генерации контента, откройте **ISG Site → Демо-наполнение** и запустите генератор ещё раз, чтобы создать недостающие демонстрационные товары.

## Как проверить результат

Ниже — ручные приёмочные сценарии. Они предназначены для проверки результата со стороны заказчика; в каждом сценарии указано ожидаемое поведение.

### 1. Проверка наполнения сайта

1. В админ-панели откройте **ISG Site → Демо-наполнение**.
2. Нажмите **Создать недостающий демо-контент**.
3. Вернитесь на эту страницу и проверьте таблицу счётчиков опубликованных записей и демозаписей.
4. Откройте главную страницу сайта, архивы решений и услуг, отдельные записи и магазин.
5. Запустите генератор повторно.

**Ожидаемый результат:** на сайте появляется демонстрационный контент, созданные материалы отмечены как демо; повторный запуск не должен создавать дубликаты уже существующих демозаписей или перезаписывать их текст. Если WooCommerce не был активен, товары появятся после его активации и повторного запуска генератора.

На пустой установке с настроенными `en` и `ru` генератор рассчитан на создание следующего демонстрационного набора: 6 решений, 7 услуг, 4 вакансии, 4 кейса и 4 новости на каждый язык; 8 служебных страниц на язык; 8 товаров и 4 категории на язык при активном WooCommerce. Это ориентир для свежей базы, а не обязательные итоговые числа, если в ней уже были записи.

### 2. Проверка настроек главной страницы

1. Перейдите в **Внешний вид → Настройки темы ISG**.
2. Измените заголовок первого экрана, например добавьте слово `TEST`.
3. Сохраните изменения и откройте главную страницу в новой вкладке.
4. Снимите отметку у одной секции (например, «Новости») и снова сохраните настройки.
5. Поменяйте основной или акцентный цвет и обновите страницу.
6. После проверки верните исходные значения и включите обратно скрытую секцию.

**Ожидаемый результат:** новый текст отображается на главной; отключённая секция скрывается; выбранный цвет меняет оформление элементов темы. Изменения не требуют правки PHP-файлов. Перестановка секций в произвольном порядке через drag-and-drop не предусмотрена.

### 3. Проверка редактирования сущностей

1. В административном меню откройте **Решения** или **Услуги** и отредактируйте одну из демонстрационных записей. Можно также создать отдельную тестовую запись.
2. Измените заголовок и основной текст. В блоке **Данные для сайта** проверьте доступные поля: подзаголовок, текст и URL кнопки, URL демоматериала, примечание о цене. У вакансий есть поля зарплаты и формата/места работы; у партнёров/кейсов — организация и год.
3. Сохраните публикацию и откройте её публичную страницу и архив соответствующего типа.
4. Проверьте, что URL кнопки остаётся внутренним адресом сайта. Внешние адреса в метаполях URL не должны сохраняться как целевые ссылки.

**Ожидаемый результат:** запись редактируется средствами WordPress, изменения видны на её странице, а архив показывает соответствующий список. Демоданные не следует принимать за утверждённые сведения о компании, открытые вакансии или подтверждённые клиентские кейсы.

### 4. Проверка магазина WooCommerce

1. В **Товары → Все товары** откройте демонстрационный товар, затем его категорию.
2. Перейдите в магазин через пункт меню или кнопку «Купить» в шапке сайта.
3. Проверьте открытие каталога, страницы категории и отдельного товара.
4. Убедитесь, что ссылка «Купить» ведёт на страницу магазина, а не на отдельный товар.

**Ожидаемый результат:** страницы WooCommerce оформлены стилями темы, каталог и карточки доступны для просмотра. Демотовары без цены специально не предназначены для покупки, поэтому отсутствие возможности добавить такой товар в корзину не является ошибкой этой демонстрационной сборки.

Чтобы отдельно проверить стандартный сценарий корзины и оформления заказа, создайте временный тестовый товар WooCommerce с тестовой ценой и включённой покупкой. Используйте только тестовую конфигурацию оплаты. Реальный платёжный провайдер в проект не подключён.

### 5. Проверка демонстрационных интеграций

1. Войдите в админ-панель с правами администратора.
2. Откройте раздел **Интеграции ISG**.
3. Последовательно нажмите кнопки для проверки оплаты, цифровой выдачи, AI-помощника и передачи в Telegram.

**Ожидаемый результат:** после каждого запуска отображается демонстрационный ответ с полями результата, названием провайдера и идентификатором операции. В сообщении прямо указывается, что внешний сервис не вызывался.

**Важно:** эти кнопки не списывают деньги, не выдают реальные цифровые товары, не отправляют сообщения в Telegram и не обращаются к AI API. Это проверка административного интерфейса и контракта ответа, а не готовность реальных интеграций.

### 6. Проверка мультиязычности

Проводите этот сценарий только после установки и настройки Polylang или WPML.

1. Настройте английский (`en`) как основной язык и русский (`ru`) как дополнительный. Включите URL языковыми каталогами и проверьте языковые ссылки на страницах записей и магазина.
2. До запуска генератора убедитесь, что оба языка созданы в плагине. Запустите **ISG Site → Демо-наполнение**.
3. Откройте английскую и русскую версии главной, записи решения и услуги; проверьте ручной переключатель языка.
4. Проверьте архивы решений и услуг по адресам `/products/`, `/services/`, а при языковом префиксе — `/ru/products/` и `/ru/services/`.
5. Откройте **ISG Site → Languages** и сверяйтесь с рекомендованными параметрами конфигурации.

**Ожидаемый результат:** при существующих и связанных переводах переключатель использует URL языковой версии, созданные выбранным плагином; демогенератор создаёт пары EN/RU и связывает их при обнаруженных настройках языков. Если плагин мультиязычности не установлен, переключатель намеренно не должен вести на фиктивные языковые URL.

**Известное ограничение:** полноценная мультиязычность WooCommerce не входит в архив. Для перевода и связывания магазина, товаров, категорий, корзины и оформления заказа требуется совместимый модуль выбранного решения (например, Polylang for WooCommerce либо соответствующий компонент WPML для WooCommerce). Поэтому не следует считать мультиязычный магазин полностью проверенным только на основании существования английских и русских страниц. Автоматическое определение языка браузера и машинный перевод также требуют отдельной настройки плагина; для машинного перевода могут потребоваться платный компонент и API-ключ.

### 7. Проверка адаптивности и базовой навигации

1. Откройте главную, архив, страницу сущности и страницу товара на широком экране.
2. В инструментах разработчика браузера переключитесь на мобильную ширину около 375–390 пикселей.
3. Проверьте открытие/закрытие мобильного меню, переходы по меню и кнопкам, чтение карточек и отсутствие горизонтальной прокрутки.
4. Используйте поиск WordPress и откройте заведомо несуществующий адрес сайта.

**Ожидаемый результат:** оформление адаптируется к узкому экрану, мобильная навигация доступна, поиск показывает результаты/пустое состояние, неизвестный адрес открывает страницу 404 темы. Это ручная визуальная проверка; автоматических браузерных end-to-end тестов в репозитории нет.

## Автоматическая проверка исходников

Из корневого каталога репозитория выполните:

```bash
./scripts/check-php.sh
```

Скрипт проверяет синтаксис PHP через `php -l` и валидность `theme.json`. Для запуска нужен PHP CLI; Python 3 используется для проверки JSON, если он установлен.

Эта проверка **не** запускает WordPress и не проверяет действия в браузере, работу WooCommerce, языкового переключателя, корзины или внешних сервисов. Эти сценарии нужно проверять на работающей тестовой установке по шагам выше.

## Структура репозитория

```text
wp-content/
  themes/isg-theme/       # шаблоны, стили, скрипты и оформление WooCommerce
  plugins/isg-site/       # сущности, метаполя, настройки, демоданные, демо-интеграции
release/                 # отдельные ZIP темы и плагина для установки в WordPress
design-preview/          # статические HTML-макеты основных экранов
content/                  # материалы и редакционные заметки по контенту
scripts/check-php.sh      # статическая проверка PHP и theme.json
```

## Что не входит в готовую реализацию

- реальные платёжные операции и подключение платёжного провайдера;
- отправка сообщений в Telegram, вызов внешнего AI API и реальная цифровая выдача;
- полноценная мультиязычная интеграция WooCommerce без отдельного совместимого расширения;
- машинный перевод без настройки сервиса, лицензии и API-ключа;
- визуальный конструктор с произвольной перестановкой секций;
- утверждённые коммерческие цены, подтверждённые данные о компании, вакансии, кейсы и юридические тексты;
- автоматические end-to-end тесты WordPress/WooCommerce.

Перед реальным запуском демоконтент необходимо заменить и проверить, магазин — настроить, а внешние интеграции — реализовать и протестировать отдельно.
